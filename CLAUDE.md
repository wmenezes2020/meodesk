## MeuDesk custom builds

- Android, Windows and macOS custom artifacts are built by
  `.github/workflows/build-custom-cliente-*.yml`.
- macOS branding lives in `Configs/AppInfo.xcconfig` (`PRODUCT_NAME`),
  `Runner/AppIcon.icns` and the `Info.plist` URL scheme; see
  `docs/SDD_MACOS_BUILD.md`.
- `scripts/apply_customizations.py` embeds branding and managed connection
  values before compilation.
- Keep `hide-server-settings` in `BUILTIN_SETTINGS`; Flutter reads that map to
  hide and block the restricted server form.
- Keep fixed ID server and public key values in `OVERWRITE_SETTINGS`; do not
  expose their concrete values in documentation or logs.
- Keep `hide-powered-by-me` in `BUILTIN_SETTINGS` and `disable-account` in
  `HARD_SETTINGS`; they remove the upstream credit and the account/login feature.
- `libs/hbb_common` is a normal in-tree directory, not a submodule. The script
  rewrites its `config.rs` at build time, so `git checkout` it after any local
  test run.

## Product name

- `config.json` -> `app_name` is the single source of truth; never hardcode it.
- `src/lang.rs` already substitutes `RustDesk` with the app name in every
  translated string, so language files must not be edited for branding.
- For anything outside that path, read the name at runtime
  (`crate::get_app_name()`, `bind.mainGetAppNameSync()`, `R.string.app_name`)
  and fall back to `apply_customizations.py` only for build metadata.
- Rationale and the out-of-scope list live in `docs/SDD_WHITELABEL_MEUDESK.md`.

## Native library and independence

- The native library is `libmeudesk`. Renaming it means touching all three
  load chains at once: `Cargo.toml`, `ffi.kt` (`System.loadLibrary`),
  `native_model.dart`, `windows/runner/main.cpp`, `windows/CMakeLists.txt`,
  `build.py` and the Android workflow's `jniLibs` copy.
- Both workflows build with `--locked`, so `Cargo.lock` must always agree with
  `Cargo.toml`.
- Android `applicationId` stays `com.carriez.flutter_hbb` — installations
  already exist and changing it would break upgrades.
- The project is AGPL-3.0 and derived from upstream: never remove `LICENCE`,
  the copyright notices, or `CompanyName`/`LegalCopyright` in `Runner.rc`.
- Upstream git dependencies are vendored into `third_party/vendor` by
  `.github/workflows/vendor-upstream-deps.yml` and redirected through
  `.cargo/config.toml`. Never hand-edit either; re-run the workflow.
- `Cargo.toml` and `Cargo.lock` keep the original upstream URLs on purpose:
  the swap is source replacement, which is what keeps `--locked` valid.

## Branding assets

- Icons and logos are generated by `scripts/generate_brand_assets.py` from
  `images/meudesk - fondo transparente.png`; never hand-edit the outputs.
- Run `python scripts/generate_brand_assets.py` from the repository root after
  changing the artwork, then commit the regenerated files.
- `.gitignore` ignores `*png`, so `flutter/assets/{icon,logo,logo_light,logo_dark}.png`
  are explicitly re-included; keep those negations when editing `.gitignore`.
- Rationale and the full asset map live in `docs/SDD_BRANDING_ASSETS.md`.

## Domain and upstream URL references

- User-facing links point to `https://meudesk.com`; the EULA link on the
  install page points at the domain root.
- Three `rustdesk.com` occurrences are intentional and must not be rebranded:
  `is_public()` in `src/common.rs` (matching our own domain there would flip
  the public-server behaviour), the update endpoint in `libs/hbb_common`
  (unreachable because `check_software_update` returns early for custom
  clients), and the `websocket.rs` / `socket_client.rs` test fixtures.
